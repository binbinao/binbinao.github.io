为什么公网这一页看不到你的真实会议

真实数据由你本机 127.0.0.1:8787 的桥接服务通过 tmeet CLI 读取，公网静态页面够不到本机服务，也不该把会议主题、参会人和入会链接放到公开站点。所以这里放的是可独立运行的演示版；日常使用与预约会议，请在你自己的机器上跑本地工作台。

CAPABILITIES

一个页面，管住整月会议

前端只通过一个 askDsh 通道与后台通信，宿主内嵌、本地服务、直开文件三种形态自动切换，不降级伪造数据。

月度日历热力图

按会议密度着色，冲突时段自动标记。整月节奏一眼看清，不用再翻聊天记录找时间。

今日会议与详情

状态、时间、主持人、入会入口集中呈现；详情弹窗里可看转写文件、云端纪要、复制邀请。

预约与统计

表单直接写入腾讯会议，等候室、云录制、转写、水印一次设好；本周会议数与时长自动汇总。

TWO MODES

REPLICATE

三步，跑在你自己的机器上

前端与桥接服务都是单文件，零依赖、不装框架。逐字落地即可，不需要重新生成页面。

STEP 01

落地两个文件

新建空目录，把资料库《工作台前端页面 index》与《serve.js 源码（逐字落地）》的产物逐字保存为 index.html 和 serve.js。

STEP 02

启动本地桥接

在该目录执行 node serve.js。服务只监听本机 8787，会自动发现 WorkBuddy 腾讯会议连接器同款 tmeet CLI。

STEP 03

授权并打开页面

在 WorkBuddy 左侧「专家 / 连接器」面板完成腾讯会议授权，再打开本地地址。顶栏变「已连接」后即同步真实会议。

Terminal · macOS / Linux 
# 1. 建目录，放入 index.html 与 serve.js（逐字复制，不要改动）
mkdir tmeeting-workbench && cd tmeeting-workbench

# 2. 启动本地桥接服务（默认 http://localhost:8787）
node serve.js

# 3. 完成腾讯会议连接器授权后，打开工作台
open http://localhost:8787/index.html
